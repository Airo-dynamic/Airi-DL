## E001：检查生成 patch 时的空白误报

影响：DEVLOG 步骤 6 中不带路径过滤的 `git diff --cached --check`，会把
`HISTORY/day002/CHANGES.patch` 的正常 unified-diff 上下文标记报为 trailing whitespace
或 space before tab。上下文空行本来就以一个空格表示，Makefile 上下文则可能以空格加 tab
开头；这些是 patch 格式，不是待回放源码中的多余空白。

处理：不要修改 patch 或重算已冻结 manifest。暂存快照后使用以下命令：

```bash
git diff --cached --check -- . ':(glob,exclude)HISTORY/day*/CHANGES.patch'
uv run python tools/history.py verify-root
```

第一条继续检查全部非生成 patch 的源码、配置和文档；第二条独立验证 patch 的 SHA-256、
闭集 manifest、完整回放、连续编号和 root/latest 一致性。不能用排除 patch 代替回放。

实际结果：未过滤命令返回空白警告；上述过滤命令及 verify-root 均通过。仓库外最终
封存副本的 19 项 Python 测试、CMake/CTest 与 ASan/UBSan 仍全部通过。

下一日需修正文档的默认检查命令；day004 CI 为生成 patch 使用单独的验证规则。

## 本地提交钩子说明

本次宿主注入的 `.git/hooks/pre-commit` 没有 shebang，其辅助脚本还会修改全局
`core.quotepath` 并引用不存在的 `/opt/.fileservice/commit/GitPreCommit`。它不是仓库文件。
完成手工门禁与暂存区检查后，提交时使用单次 `git -c core.hooksPath=<空临时目录>`，
不编辑宿主钩子，不改变 Git 全局配置。普通开发环境按 DEVLOG 正常提交即可。
